# NotEnoughTranslator 模块架构

[English](../English/ModuleArchitecture.md) | [返回首页](../../README.md) | [翻译与资源指南](翻译指南.md)

本文面向插件开发与接入工作，说明当前骨架的职责边界。资源格式与翻译包制作方法见[翻译指南](翻译指南.md)。

## 1. 当前实现范围

| 模块 | 已实现 | 尚未接入或验证 |
| --- | --- | --- |
| UI / I2 | CSV 加载、中央查询 Hook、参数与 AdvancedFormat 处理、强制刷新 | 实机 UI 覆盖率与字体适配 |
| 通用文本 | JSONL 加载、精确匹配、正则替换、捕获组二次翻译、查询接口、系统消息队列显示 Hook、剧情显示 Hook（对白、说话人名、选项） | TMP / uGUI 等其余具体显示入口 |
| 纹理替换 | PNG / JPG / JPEG 资源索引、按纹理名读取数据、精灵加载入口与 uGUI 图片赋值处原地替换、未命中时导出原图、其余精灵按精灵图名称替换 uGUI `Image` 精灵图、重载与卸载 | 非 Texture2D 纹理与 uGUI 图片之外的异步加载路径 |
| 性格标签（可选） | JSONL 加载、通过反射的标签后置补丁 | 实机检查女主角状态面板 |
| 随机名字（可选） | JSONL 加载、随机名字方法和按钮后置补丁 | 实机检查每个调用方 |

这是基础骨架，不代表已经覆盖游戏全部文本或图片。各模块可以独立启用或关闭。

XUAT 互操作是共享设施，不是另一个翻译模块；它保护已登记的 NET 译文，但不会自动补齐 TMP / uGUI 显示 Hook。

## 2. 架构约束

- 不注册新语言，不新增 `LanguageSource`，不修改游戏语言或 `Product.supportMultiLanguage`。
- 不提供 JAT 的译文语言选择或多语言字符串切分；翻译包直接提供要显示的译文。
- 不做 LRU 或文本命中/未命中缓存。正则在加载时编译，查询时直接匹配。
- XUAT 防重译只登记已返回的译文，不保存原文到译文的查询缓存，也不添加、检测或剥离特殊标记。
- 正则使用 .NET 语法，保留捕获内容的二次精确翻译，不做自定义 `Unescape`。
- 通用文本模块只读取 JSONL，不引入 TXT 兼容层。性格标签模块和随机名字模块使用相同的 JSONL 格式。
- 不移植旧 NGUI、COM3D2 文件系统或未经验证的全局 TMP setter 补丁。
- 翻译发生在显示或查询边界，不就地改写游戏业务数据。

## 3. 数据流

以下路径相对于 `BepInEx/NotEnoughTranslator`，沿用 JAT 的模块边界，但没有语言目录：

| 模块 | 资源加载 | 导出输出 |
| --- | --- | --- |
| UI / I2 | `UI/Text` | `Dump/UI/Text` |
| 通用文本 | `Text` | `Dump/Text` |
| 纹理替换 | `Texture` | `Dump/Texture` |
| 性格标签 | `Personality` | 无 |
| 随机名字 | `RandomName` | 无 |

各加载器只扫描自己的资源子树，不扫描公共根目录或导出目录。ZIP 翻译包也必须放入对应文本模块的子树。

```text
UI/Text 下的 CSV / ZIP
  -> AsyncTranslationLoader
  -> TranslationLoadResult.I2Terms
  -> UITranslateManager
  -> UITextTranslatePatch
  -> I2 显示流程

Text 下的 JSONL / ZIP
  -> AsyncTranslationLoader
  -> TextTranslations / TextRegexTranslations
  -> TextTranslateManager
  -> TextTranslatePatch（系统消息队列、对白、说话人名、选项）
  -> 待接入的 TMP / uGUI 显示 Hook

Texture 下的图片
  -> TextureReplacementCatalog 路径索引
  -> TextureReplaceManager
  -> TextureReplacePatch（GameResource.LoadAsset<Sprite> / Image.sprite，整张纹理原地替换）
  -> ImageSpriteReplacePatch（uGUI Image 精灵图：图集子图及其余精灵）

Personality 下的 JSONL / ZIP
  -> AsyncTranslationLoader
  -> TextTranslations（忽略正则行）
  -> PersonalityTranslateManager（ScopedLookupCatalog）
  -> PersonalityTextTranslatePatch
  -> 女主角状态面板标签，在游戏写入之后

RandomName 下的 JSONL / ZIP
  -> AsyncTranslationLoader
  -> TextTranslations（忽略正则行）
  -> RandomNameTranslateManager（ScopedLookupCatalog）
  -> RandomNameTranslatePatch -> 随机名字方法，在游戏保存名字之前
  -> RandomNameButtonTranslatePatch -> 四个名字面板的 SetRandomName，写入所选输入框
```

`TextTranslatePatch` 还包含剧情入口：`AdvSystem.Utility.ReplaceCharaName(string)` 上的前置与后置补丁，以及 `ADVKagManager.TagHitRet` 和 `TagChoicesSet` 上各一个前置补丁与清理补丁。在选项标签内，游戏会调用两次 `ReplaceCharaName(string)`，第二次作用于第一次的结果；只有第一次调用查询译文。当前置补丁替换了文本，或收到已登记的 NET 输出（例如命中把 `[HF]` 映射为自身的词条后的 `[HF]`）时，后置补丁为 XUAT 登记最终文本。如果前置补丁收到 NET 已登记的文字，而当前剧情上下文有它的上下文词条，前置补丁使用该词条。

两个文本模块共享加载基础设施，但资源通道和消费端彼此分开。`TranslationCatalog` 承担精确与正则查询，`ResourceModule<T>` 负责加载任务和主线程结果发布。

## 4. UI / I2 查询覆盖

目标是 CRC 版本的 `LocalizationManager.TryGetTranslation`，包含新增的 `Localize.AdvancedFormat` 参数。找不到预期签名时，记录错误并停用 UI 模块，而不是强行切换语言。

查询行为：

1. 指定了 `overrideLanguage` 时，不覆盖原结果；该调用中的嵌套 term 查询也不覆盖。
2. 自定义字典未命中时，保留原译文与成功标志。
3. 原 term 元数据为非文本类型时，不将资源标识当作文字替换。
4. 命中后，对新译文按原条件执行参数替换、RTL 处理和 `AdvancedFormat.Format`。
5. 全部处理成功且结果不是空白时，才替换译文并设置成功标志。
6. 处理异常时保留原结果，同一 term 每轮资源加载只警告一次。

不需要修改游戏语言列表、语言索引或 Source 优先级。UI 译文格式要求见[翻译指南](翻译指南.md)。

## 5. 生命周期与线程

各管理器均提供 `Init` / `Reload` / `Unload`，在 Unity 主线程调用。资源加载由完成回调驱动，不再逐帧调用 `Tick`。

- 翻译文件读取、JSON / CSV 解析、正则编译与纹理路径扫描在后台执行，不调用 Unity API。
- 等待加载任务时捕获 Unity 同步上下文，完成后回到主线程发布结果，不轮询任务状态。
- 重载期间保留上次快照；被取消或过期的任务不会回写。
- 文件读取失败保留旧快照；成功加载空目录会清空该模块旧资源。
- 纹理字节在查询时读取，不缓存图片内容；路径扫描与图片读取不是同一个阶段。已生成的 UI 精灵图在下次发布或卸载前把像素保留在 GPU 内存中，编码字节不保留。
- 配置变更事件向主线程投递重载请求，合并尚未处理的请求。插件 `Update` 只检测重载和导出落盘快捷键，不轮询资源加载、导出缓冲或互操作初始化。

### 显示刷新

UI 资源发布时，若 `LocalizeManager.isSetupCompleted` 已为 true，立即调用 `LocalizeAll(true)`；否则由该属性 setter 的后置回调在初始化完成时触发待处理刷新，不使用逐帧循环。

UI 翻译启用时，`UITranslateManager.Init` 统一安装 I2 翻译和本地化就绪补丁。`Unload` 移除翻译 Hook，但保留就绪回调，确保先关闭 UI 翻译也不会丢失待处理的原生刷新。插件销毁时由 `UITranslateManager.Shutdown` 卸载 UI 模块、清空待刷新状态并移除就绪 Hook。插件入口只调用管理器生命周期方法，不直接管理 UI 补丁。全过程不切换游戏语言。

如果游戏本来就没有某个 term 的原文，I2 返回 null 只是不覆盖当前组件文本，不保证还原旧文本。

通用文本已在系统消息队列入口替换显示值：重载后新排队的消息使用新词库，已排队或已显示的旧消息不回溯刷新。原地替换的纹理在资源下次加载或赋值时生效，不会自动还原，uGUI Hook 的 UI 精灵图则在每次发布时还原并重建（见下文）；其余文本入口目前只更新后续查询结果；已有显示对象如何刷新，要在接入具体显示入口时实现。性格标签在面板下次打开时更新。随机名字模块重载后只影响之后生成的名字，已保存的名字不变。

剧情文本在重载或开关变化后不会刷新，下一行起使用新数据。屏幕上的当前行、已打开的选项和回看记录保留原有文字。游戏的 `MessageData` 只保存最终文本，原文已不存在，回看记录保存的也是这份最终文本的副本。要刷新就需要一张从显示文本反查原文的映射，这接近 NET 不允许的原文到译文的缓存。

### UI 精灵图

发布含有条目的纹理快照且 `EnableUISpriteReplace` 开启时，`TextureReplaceManager` 安装 `ImageSpriteReplacePatch`：`Image.sprite` 与 `Image.overrideSprite` setter 上的前置补丁，以及 `Image.OnEnable` 上的后置补丁。查找键是 `Sprite.name` 而不是纹理名，因为大多数 UI 精灵图共用大型图集页。索引为空或开关关闭时不安装任何 Hook。

两个纹理 Hook 分工处理。`TextureReplacePatch` 原地替换整张纹理。`ImageSpriteReplacePatch` 处理其余精灵图：图集子图，以及 `TextureReplacePatch` 未替换的整张纹理，例如只经过 `overrideSprite` 的精灵图。它的 setter 前置补丁声明 `after` 为 `TextureReplacePatch` 的 ID，因此 `TextureReplacePatch` 先看到每个精灵图。覆盖整张纹理的精灵图，若 `TextureReplacePatch.IsApplied` 报告其纹理已处理，则保持不变。注册表对自己生成的每张纹理调用 `TextureReplacePatch.MarkApplied`，因此 `TextureReplacePatch` 不会向其中解码。

`ReplacementSpriteRegistry` 在主线程为每个原始 Sprite 对象生成一张纹理和一个 Sprite，并持有两者。它维护两张表（原始到替换、替换到原始），没有按名称索引的表。每次发布时，`TextureReplaceManager` 先让注册表把所有 `Image` 上的原始精灵图还原、销毁其生成的对象并清空两张表；再调用 `TextureReplacePatch.Reset()`，使修改过的整张纹理图片在下次加载或赋值时重新解码；最后由注册表把每个已启用且处于激活状态的 Image 的 sprite 重新赋给自身，让两个 setter 前置补丁按顺序执行。隐藏的 Image 在游戏启用它时获得替换，因此重载只生成屏幕上的图片。`Unload` 先移除 Hook，再还原并销毁。加载失败不会发布任何结果，因此原有替换保持不变。

### Harmony 补丁 ID

与 JAT 一样，每个补丁类显式声明稳定、全小写的 `HarmonyId`。同一补丁类的前置、后置和异常清理方法共用所属 ID，不同补丁类使用独立 ID。安装、失败回滚和卸载使用同一个 Harmony 实例，`UnpatchSelf()` 仅移除该 ID 所属的补丁。

| 补丁归属 | Harmony ID |
| --- | --- |
| `UITextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.uitexttranslatepatch` |
| `LocalizationReadyPatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.localizationreadypatch` |
| `TextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.text.texttranslatepatch` |
| `TextureReplacePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.texture.texturereplacepatch` |
| `XUATInterop` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.utils.xuatinterop` |
| `PersonalityTextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.personalitytexttranslatepatch` |
| `RandomNameTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.status.randomnametranslatepatch` |
| `RandomNameButtonTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.randomnamebuttontranslatepatch` |
| `ImageSpriteReplacePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.texture.imagespritereplacepatch` |

这些 ID 用于 Harmony 补丁归属，不是 BepInEx 插件 GUID；插件 GUID 保持不变。后续新增补丁类也应声明独立 ID，不复用模块级简写。

三个补丁类都沿用 JAT 的组织方式：`UITextTranslatePatch` / `TextTranslatePatch` 里的方法只挂 `[HarmonyPatch]` / `[HarmonyPrefix]` 等特性，由对应的 Manager 直接调用 `Harmony.CreateAndPatchAll` 一次性安装，异常时 `UnpatchSelf` 回滚。新增入口只要在同一个类里加一个带特性的方法即可，不需要改安装代码。`UITextTranslatePatch` 的目标方法含 `out string` 参数，无法写进特性构造参数，改用 `[HarmonyTargetMethod]` 按完整签名解析；签名不匹配时抛异常，UI 模块随即停用。`TextureReplacePatch` 的目标是 `GameResource.LoadAsset<Sprite>(string)`（泛型方法），同样用 `[HarmonyTargetMethod]` 构造；它以 `WfSystem.FileSystem.dll` 为编译引用。`LocalizationReadyPatch` 带运行时判断（本地化已完成就不再挂接），仍由补丁类自身 `Install` / `Uninstall`。

## 6. 接入接口

| 管理器 | 消费接口 | 结果 |
| --- | --- | --- |
| `UITranslateManager` | `TryGetTranslation(term, out translation)` | 按 I2 term 查询文字 |
| `TextTranslateManager` | `TryGetTranslation(sourceText, out translation)` | 精确匹配优先，再尝试正则 |
| `TextTranslateManager` | `TryGetTranslation(sourceText, file, label, out translation)` | 先查上下文词条（剧情文件与标签），再走与上一行相同的路径 |
| `TextureReplaceManager` | `TryGetReplacement(textureName, out data)` | 获取替换图片的编码字节 |
| `TextureReplaceManager`（内置） | uGUI `Image.sprite` / `Image.overrideSprite` setter、`Image.OnEnable` | 用同一图片字节生成的替换精灵图，按精灵图名称匹配 |
| `PersonalityTranslateManager` | `TryGetTranslation(original, out translation)` | 精确匹配性格标签 |
| `RandomNameTranslateManager` | `TryGetTranslation(original, out translation)` | 精确匹配生成的随机名字 |

五个管理器都暴露 `IsLoaded`、`IsLoading` 和 `EntryCount`，并且都暴露 `IsHookInstalled`。文本模块另有 `ExactCount` / `RegexCount` / `ContextCount`；纹理模块另有 `HasReplacement`（只查索引、不读文件）以及 `IsSpriteHookInstalled` / `ReplacedSpriteCount`。随机名字模块还暴露 `IsButtonHookInstalled`。

性格标签 Hook 通过反射访问 `TMP_Text.text`，因此构建不需要 `Unity.TextMeshPro.dll`。安装时依次检查：`HeroineEditUIStatus` 声明了实例字段 `m_personalityText`；该字段类型派生自 `TMPro.TMP_Text`；`TMP_Text` 声明了可读写的 `string` 属性 `text`。任一检查失败时，日志会写明失败的检查，且不安装补丁。

随机名字模块是“翻译发生在显示或查询边界”这条规则（见第 2 节）的一个明确例外。两个 Hook 改变的值随后都会被游戏保存到角色状态和存档中。方法后置补丁改变游戏保存的默认名字。按钮后置补丁通过输入框的 `text` setter 把译文写入所按按钮对应的输入框，随后游戏自己的 `onValueChanged` 监听器像保存手动输入的名字一样保存它。NET 本身不写入任何状态成员。按钮 Hook 只读取所按按钮对应的输入框，因此手动输入的名字永远不会被翻译。基于这些原因，`8RandomName` 开关默认关闭。

按钮 Hook 通过反射访问 `TMP_InputField.text`，因此构建不需要 `Unity.TextMeshPro.dll`。安装时对四个面板的每个字段依次检查：面板声明了该实例字段；字段类型派生自 `TMPro.TMP_InputField`；`TMP_InputField` 声明了可读写的 `string` 属性 `text`。任一检查失败时，日志会写明失败的检查，且不安装按钮补丁。字段检查失败时，日志还会写明面板和字段。管理器分别独立安装方法补丁和按钮补丁，并记录两者的状态。

### 剧情上下文查询

带 `file` 和 `label` 的重载供知道剧情位置的调用方使用，例如剧情 Hook。原有重载等同于两者都传 `null` 的调用，结果不变。

- `TranslationCatalog` 另存一个以 (file, label, original) 为键的词典，只保存有歧义原文的词条，即存在多个不同译文的原文。`ContextCount` 是它的条目数。当某原文后加载的精确词条与前一条的译文不同时，JSONL 处理器把该原文标记为有歧义。
- 查询顺序：上下文词典、精确词典、正则规则。只有上下文词典非空、`label` 非空且规范化后的 `file` 非空时才会查询上下文词典。
- 目录部分和一个 `.ks` 后缀由 `TranslationCatalog` 去掉后，`file` 不区分大小写比较；`label` 和 `original` 按 Ordinal 比较。`TranslationCatalog` 不缓存命中或未命中结果。
- 一条词条需要同时有 `file` 和 `label`。JSONL 处理器会跳过 `file` 或 `label` 不是字符串的词条。
- 文本加载日志的格式为 `[Text] Loaded/已加载 <exact> exact, <regex> regex, <context> context, <skipped> skipped, <ms> ms`。

字段格式见[资源指南](翻译指南.md#411-剧情上下文file-与-label)。

### 导出基础设施

`DumpManager` 是共享基础设施，不是另一个翻译模块。插件一次性初始化导出目录，移除各模块 Hook 后关闭导出；通过锁保护本次运行的去重集合与缓冲写入，不使用定时器或逐帧轮询。

| 接口 | 用途 |
| --- | --- |
| `UITranslateManager.DumpTerm(term, original)` | UI 快照发布后导出未翻译词条，包含发布时触发的首次强制刷新 |
| `DumpManager.DumpTerm(term, original)` | 将调用方确认未翻译的词条缓冲为 CSV 模板 |
| `DumpManager.DumpText(original)` | 将调用方确认未翻译的通用文本缓冲为 JSONL 模板 |
| `DumpManager.DumpText(original, file, label)` | 同上，模板中带有 `file` 和 `label`；按 (file, label, original) 去重 |
| `DumpManager.DumpTexture(textureName, pngData)` | 使用与替换索引相同的文件名规则写入原图 PNG，不覆盖已有文件；由纹理补丁在未命中时调用 |
| `DumpManager.Flush()` | 写入两个文本缓冲并返回是否全部成功 |

I2 查询 Hook 转交未翻译的文本词条，不修改游戏原结果。通用文本正常查询接口仅在加载完成后导出未命中的原文；`IsInTranslationDictionary` 仍只探测词库，不产生导出副作用。首次加载期间不会把尚未就绪的整个词库误当作缺失翻译导出。通用文本显示 Hook 目前覆盖系统消息队列和剧情文本；纹理补丁负责在未命中时编码原图并交给导出设施，TMP / uGUI 显示入口仍需游戏接入。

文本写入失败会保留缓冲并尝试恢复原文件长度；PNG 通过临时文件和不覆盖目标的移动操作发布。导出去重记录在资源重载时保留，与 XUAT 的已译文字登记集合彼此独立，不作为翻译查询缓存。开关、阈值与落盘触发条件见[资源指南](翻译指南.md)。

## 7. XUAT 互操作

采用 JAT 的判定拦截方式，反射查找已加载的 `XUnity.AutoTranslator.Plugin.Core`，不需要编译期引用或把 XUAT DLL 放入 `lib`。匹配下列类型中返回 `bool`、第一个参数为 `string` 的 `IsTranslatable` 方法：

- `Utilities.LanguageHelper`
- `TextTranslationCache`
- `CompositeTextTranslationCache`

判定顺序：

1. 输入已登记为 NET 的 UI、通用文本或性格标签译文时，返回 `false`，阻止 XUAT 再翻译。
2. 通用文本显示 Hook 已接管，且当前原文能通过精确或正则查询翻译时，也返回 `false`，交给 NET。
3. 其余情况保留 XUAT 原判定；NET 判定发生异常时同样放行，不把全部文本误封。

**第 2 项只在显示 Hook 确实安装后生效。** `TextTranslateManager.Init` 按 `TextTranslatePatch.Install()` 的结果调用 `SetDisplayHooksInstalled`，移除补丁或卸载模块时复位为 false；这不是供翻译包开启的设置。显示 Hook 通过一个补丁类覆盖多个入口，当前包括系统消息队列和剧情文本，因此该拦截意味着词库内原文不再交给 XUAT，覆盖面仍限于已接入的入口。

该标志是全局的。开启期间，XUAT 会跳过 NET 的 `Text` 词库能翻译的所有字符串，包括没有任何 NET Hook 显示的字符串。数据规则：不要把只在其他 UI 显示的词条放进 `Text`。Hook 安装后，XUAT 将不再翻译这些 UI 文字。这同样适用于剧情和其他 UI 都会显示的原文，例如与菜单项相同的选项。XUAT 此时也会跳过该菜单项，即使 XUAT 文件或翻译服务中有它的译文。若该菜单项必须交给 XUAT，就不要添加这条词条，剧情中的这一行也会交给 XUAT。

译文登记与查询接口：

- 通用文本 `TryGetTranslation` 在互操作启用时跳过已登记的 NET 译文，并在成功返回后登记结果。
- 互操作启用时，`TryGetContextTranslation` 只读取上下文词条，不跳过已登记的文字，也不导出，并登记命中的结果。剧情入口用它查询带文件与标签的已登记文字。
- `IsInTranslationDictionary` 只判断翻译能力，不登记候选结果，避免一次探测就被当作已经输出。
- UI 在参数、RTL 和 `AdvancedFormat` 全部成功后，才通过 `MarkTranslated` 登记最终结果，不登记未展开的模板。
- UI、通用文本和性格标签管理器分别提供 `IsNetTranslatedText` 和 `MarkTranslated`。性格标签 Hook 先登记再写入标签，因为 XUAT 的 TMP setter Hook 可能在写入过程中判定新文字。后续显示 Hook 若还会修改返回值，应登记实际提交的最终文本。
- 这些管理器各自使用独立、线程安全、Ordinal 匹配的译文集合；成功发布新资源或卸载模块时清空各自集合，加载失败仍保留旧状态。
- 集合只用于防重译，不用来返回缓存译文；不包含未命中记录或 LRU，也不做额外规范化、反转义或占位符推测。

插件 `Start` 尝试初始化；晚加载的程序集通过加载事件向 Unity 同步上下文投递回调，在主线程安装补丁，不依赖 `Update` 轮询。互操作卸载后，已排队的回调不再执行安装。未安装 XUAT 时保持普通 NET 行为；签名不兼容或安装失败会记录警告。卸载只移除 NET 自己的 Harmony 补丁，并取消程序集加载事件订阅。

默认启用 `2General` 下的 `EnableXUATInterop/启用 XUAT 互操作`。`XUATInterop.IsInstalled` 和 `PatchedMethodCount` 可用于接入诊断。反射兼容检查不等于真实 XUAT 版本或游戏运行验证。

实现见 [XUATInterop.cs](../../CRC3D3.NotEnoughTranslator.Plugin/Utils/XUATInterop.cs) 和 [TranslatedTextRegistry.cs](../../CRC3D3.NotEnoughTranslator.Plugin/Translation/TranslatedTextRegistry.cs)。

## 8. 后续接入要求

- 通用文本 Hook 只替换显示值，不修改兼作业务键的名称、CSV 数据或游戏状态。
- 通用文本新增显示入口统一加入 `Hooks/Text/TextTranslatePatch.cs`，复用同一个 Harmony ID 和 `Translate` 辅助方法：加一个带 `[HarmonyPatch]` 的方法即可被 `PatchAll` 装上，不按入口另建补丁类。
- 需要处理 I2 调用上下文隔离，避免二次翻译 I2 已处理的显示结果。
- 不能仅凭组件是否挂了 `Localize` 就永久跳过通用翻译；同一个组件仍可能被直接赋值。
- 纹理接入需在 Unity 主线程创建与管理 `Texture` / `Sprite`，明确原资源与替换资源的生命周期。uGUI 精灵图 Hook 持有自己生成的纹理和 Sprite，并在每次发布和卸载时还原原始对象。
- 不将当前查询接口或加载计数视为实机覆盖率证明。

## 9. 构建

目标环境：.NET Framework 4.8 / Unity 2022.3 / BepInEx 5。

将 CRC 对应版本的下列程序集放入仓库根目录 `lib`：

- `I2.Localization.dll`
- `WfSystem.FileSystem.dll`
- `UnityEngine.UI.dll`
- `Assembly-CSharp.dll`
- `Assembly-CSharp-firstpass.dll`

在仓库根目录执行：

```powershell
dotnet build CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin.csproj -c Release
```

异步使用 `Task`，不引入 `System.Threading.Tasks.Extensions` / `ValueTask` 的额外运行时依赖。编译成功不等于完成实机验证。

CI 编译同一个工程：`.github/workflows/build.yml` 会先把这三个程序集从私有仓库 `MeidoPromotionAssociation/CRC3D3.GameLibs` 拉到 `lib`，所以它们不会被提交进这个公开仓库。该仓库按游戏版本分目录（如 `2.49.2/`、`demo2/`），要编哪个版本由 `.github/scripts/fetch_game_libs.sh` 顶部的 `DEFAULT_VERSION` 决定，也可用仓库变量 `GAME_LIBS_VERSION` 覆盖。推送与 `PluginVersion` 一致的 tag 时还会跑 `.github/workflows/release.yml`，完成打包与发布。
