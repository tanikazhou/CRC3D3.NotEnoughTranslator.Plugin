# NotEnoughTranslator 模块架构

[English](../English/ModuleArchitecture.md) | [返回首页](../../README.md) | [翻译与资源指南](翻译指南.md)

本文面向插件开发与接入工作，说明当前骨架的职责边界。资源格式与翻译包制作方法见[翻译指南](翻译指南.md)。

## 1. 当前实现范围

| 模块 | 已实现 | 尚未接入或验证 |
| --- | --- | --- |
| UI / I2 | CSV 加载、中央查询 Hook、参数与 AdvancedFormat 处理、强制刷新 | 实机 UI 覆盖率与字体适配 |
| 通用文本 | JSONL 加载、精确匹配、正则替换、捕获组二次翻译、查询接口、系统消息队列显示 Hook、TMP / uGUI 文本显示 Hook | 剧本等其余具体显示入口、实机覆盖率 |
| 纹理替换 | PNG / JPG / JPEG 资源索引、按纹理名读取数据、精灵加载入口与 uGUI 图片赋值处原地替换、未命中时导出原图、重载与卸载 | 图集子图、非 Texture2D 纹理与异步加载路径 |

这是基础骨架，不代表已经覆盖游戏全部文本或图片。三个模块可以独立启用或关闭。

XUAT 互操作是共享设施，不是第四个翻译模块；它保护已登记的 NET 译文，但不会自动补齐通用文本显示 Hook。

## 2. 架构约束

- 不注册新语言，不新增 `LanguageSource`，不修改游戏语言或 `Product.supportMultiLanguage`。
- 不提供 JAT 的译文语言选择或多语言字符串切分；翻译包直接提供要显示的译文。
- 不做 LRU 或文本命中/未命中缓存。正则在加载时编译，查询时直接匹配。
- XUAT 防重译只登记已返回的译文，不保存原文到译文的查询缓存，也不添加、检测或剥离特殊标记。
- 正则使用 .NET 语法，保留捕获内容的二次精确翻译，不做自定义 `Unescape`。
- 通用文本模块只读取 JSONL，不引入 TXT 兼容层。
- 不移植旧 NGUI 或 COM3D2 文件系统补丁。全局 TMP 或 uGUI setter 补丁必须具备第 8 节的调用上下文和第 7 节的按组件记录，并经过游戏内验证。
- 翻译发生在显示或查询边界，不就地改写游戏业务数据。

## 3. 数据流

以下路径相对于 `BepInEx/NotEnoughTranslator`，沿用 JAT 的模块边界，但没有语言目录：

| 模块 | 资源加载 | 导出输出 |
| --- | --- | --- |
| UI / I2 | `UI/Text` | `Dump/UI/Text` |
| 通用文本 | `Text` | `Dump/Text` |
| 纹理替换 | `Texture` | `Dump/Texture` |

各加载器只扫描自己的资源子树，不扫描公共根目录或导出目录。ZIP 翻译包也必须放入对应文本模块的子树。

```text
UI/Text 下的 CSV / ZIP
  -> AsyncTranslationLoader
  -> TranslationLoadResult.I2Terms
  -> UITranslateManager
  -> UITextTranslatePatch
  -> I2 显示流程

Text 下的 JSONL / ZIP
  -> AsyncTranslationLoader
  -> TextTranslations / TextRegexTranslations
  -> TextTranslateManager
  -> TextTranslatePatch（系统消息队列 / TMP_Text / UI.Text）
  -> DisplayTextRecords（按组件记录的显示状态）

Texture 下的图片
  -> TextureReplacementCatalog 路径索引
  -> TextureReplaceManager
  -> TextureReplacePatch（GameResource.LoadAsset<Sprite> / Image.sprite）
```

两个文本模块共享加载基础设施，但资源通道和消费端彼此分开。`TranslationCatalog` 承担精确与正则查询，`ResourceModule<T>` 负责加载任务和主线程结果发布。

TMP / uGUI 入口为每个改写过的文字组件在 `DisplayTextRecords` 中保存一条显示记录，供第 5 节的刷新和第 8 节的回读使用。记录从不回答查询（见第 7 节）。

## 4. UI / I2 查询覆盖

目标是 CRC 版本的 `LocalizationManager.TryGetTranslation`，包含新增的 `Localize.AdvancedFormat` 参数。找不到预期签名时，记录错误并停用 UI 模块，而不是强行切换语言。

查询行为：

1. 指定了 `overrideLanguage` 时，不覆盖原结果；该调用中的嵌套 term 查询也不覆盖。
2. 自定义字典未命中时，保留原译文与成功标志。
3. 原 term 元数据为非文本类型时，不将资源标识当作文字替换。
4. 命中后，对新译文按原条件执行参数替换、RTL 处理和 `AdvancedFormat.Format`。
5. 全部处理成功且结果不是空白时，才替换译文并设置成功标志。
6. 处理异常时保留原结果，同一 term 每轮资源加载只警告一次。

不需要修改游戏语言列表、语言索引或 Source 优先级。UI 译文格式要求见[翻译指南](翻译指南.md)。

## 5. 生命周期与线程

三个管理器均提供 `Init` / `Reload` / `Unload`，在 Unity 主线程调用。资源加载由完成回调驱动，不再逐帧调用 `Tick`。

- 翻译文件读取、JSON / CSV 解析、正则编译与纹理路径扫描在后台执行，不调用 Unity API。
- 等待加载任务时捕获 Unity 同步上下文，完成后回到主线程发布结果，不轮询任务状态。
- 重载期间保留上次快照；被取消或过期的任务不会回写。
- 文件读取失败保留旧快照；成功加载空目录会清空该模块旧资源。
- 纹理字节在查询时读取，不缓存图片内容；路径扫描与图片读取不是同一个阶段。
- 配置变更事件向主线程投递重载请求，合并尚未处理的请求。插件 `Update` 只检测重载和导出落盘快捷键，不轮询资源加载、导出缓冲或互操作初始化。

### 显示刷新

UI 资源发布时，若 `LocalizeManager.isSetupCompleted` 已为 true，立即调用 `LocalizeAll(true)`；否则由该属性 setter 的后置回调在初始化完成时触发待处理刷新，不使用逐帧循环。

UI 翻译启用时，`UITranslateManager.Init` 统一安装 I2 翻译和本地化就绪补丁。`Unload` 移除翻译 Hook，但保留就绪回调，确保先关闭 UI 翻译也不会丢失待处理的原生刷新。插件销毁时由 `UITranslateManager.Shutdown` 卸载 UI 模块、清空待刷新状态并移除就绪 Hook。插件入口只调用管理器生命周期方法，不直接管理 UI 补丁。全过程不切换游戏语言。

如果游戏本来就没有某个 term 的原文，I2 返回 null 只是不覆盖当前组件文本，不保证还原旧文本。

通用文本已在系统消息队列入口替换显示值：重载后新排队的消息使用新词库，已排队或已显示的旧消息不回溯刷新。每次发布通用文本快照时，TMP / uGUI 入口在主线程遍历显示记录：仍存活的组件改写为新快照中的译文；新快照没有对应译文时，写回原文并删除记录。带有第 8 节排除写入者标记的组件会被跳过。这项刷新只覆盖本 Hook 翻译过的组件，其他屏幕文字要到下次写入或 `OnEnable` 时才更新。卸载时先移除补丁，再把仍存活的已记录组件写回原文；`SceneManager.sceneUnloaded` 时清理已销毁组件的记录。其余文本入口与纹理模块目前只更新后续查询结果；已有显示对象如何刷新，要在接入具体显示入口时实现。

### Harmony 补丁 ID

与 JAT 一样，每个补丁类显式声明稳定、全小写的 `HarmonyId`。同一补丁类的前置、后置和异常清理方法共用所属 ID，不同补丁类使用独立 ID。安装、失败回滚和卸载使用同一个 Harmony 实例，`UnpatchSelf()` 仅移除该 ID 所属的补丁。

| 补丁归属 | Harmony ID |
| --- | --- |
| `UITextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.uitexttranslatepatch` |
| `LocalizationReadyPatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.localizationreadypatch` |
| `TextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.text.texttranslatepatch` |
| `TextureReplacePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.texture.texturereplacepatch` |
| `XUATInterop` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.utils.xuatinterop` |

这些 ID 用于 Harmony 补丁归属，不是 BepInEx 插件 GUID；插件 GUID 保持不变。后续新增补丁类也应声明独立 ID，不复用模块级简写。

三个补丁类都沿用 JAT 的组织方式：`UITextTranslatePatch` / `TextTranslatePatch` 里的方法只挂 `[HarmonyPatch]` / `[HarmonyPrefix]` 等特性，由对应的 Manager 直接调用 `Harmony.CreateAndPatchAll` 一次性安装，异常时 `UnpatchSelf` 回滚。新增入口只要在同一个类里加一个带特性的方法即可，不需要改安装代码。`UITextTranslatePatch` 的目标方法含 `out string` 参数，无法写进特性构造参数，改用 `[HarmonyTargetMethod]` 按完整签名解析；签名不匹配时抛异常，UI 模块随即停用。`TextureReplacePatch` 的目标是 `GameResource.LoadAsset<Sprite>(string)`（泛型方法），同样用 `[HarmonyTargetMethod]` 构造；它以 `WfSystem.FileSystem.dll` 为编译引用。`LocalizationReadyPatch` 带运行时判断（本地化已完成就不再挂接），仍由补丁类自身 `Install` / `Uninstall`。

TMP / uGUI 入口以及第 8 节的调用上下文和回读上下文，同样是 `TextTranslatePatch` 里带特性的方法，与系统消息入口由同一次 `CreateAndPatchAll` 安装。编译库中没有的目标类型使用字符串形式 `[HarmonyPatch("<type>, Assembly-CSharp", "<method>")]`。安装是全有或全无的：运行中的游戏缺少任一目标时，`UnpatchSelf` 回滚整个类，通用文本只提供查询，系统消息入口也不例外。例如 `demo2` 版本没有 `CRCRomanceSystem.RomanceMenuControl`，因此显示 Hook 在该版本上不会安装。

## 6. 接入接口

| 管理器 | 消费接口 | 结果 |
| --- | --- | --- |
| `UITranslateManager` | `TryGetTranslation(term, out translation)` | 按 I2 term 查询文字 |
| `TextTranslateManager` | `TryGetTranslation(sourceText, out translation)` | 精确匹配优先，再尝试正则 |
| `TextTranslateManager` | `TryGetDisplayTranslation(sourceText, out translation)` | 跳过规则与登记方式同 `TryGetTranslation`，但从不导出；供需要带上下文导出的显示入口使用 |
| `TextureReplaceManager` | `TryGetReplacement(textureName, out data)` | 获取替换图片的编码字节 |

三个管理器都暴露 `IsLoaded`、`IsLoading` 和 `EntryCount`，并且都暴露 `IsHookInstalled`。文本模块另有 `ExactCount` / `RegexCount`；纹理模块另有 `HasReplacement`（只查索引、不读文件）。

### 导出基础设施

`DumpManager` 是共享基础设施，不是另一个翻译模块。插件一次性初始化导出目录，移除各模块 Hook 后关闭导出；通过锁保护本次运行的去重集合与缓冲写入，不使用定时器或逐帧轮询。

| 接口 | 用途 |
| --- | --- |
| `UITranslateManager.DumpTerm(term, original)` | UI 快照发布后导出未翻译词条，包含发布时触发的首次强制刷新 |
| `DumpManager.DumpTerm(term, original)` | 将调用方确认未翻译的词条缓冲为 CSV 模板 |
| `DumpManager.DumpText(original)` | 将调用方确认未翻译的通用文本缓冲为 JSONL 模板 |
| `DumpManager.IsTextDumped(original)` | 无副作用地检查该通用文本是否已在本次运行的去重集合中 |
| `DumpManager.DumpDisplayText(original, scene, path)` | 与 `DumpText` 使用相同的前置检查和去重，JSONL 记录额外写入 `scene` 和 `path` 字段 |
| `DumpManager.DumpTexture(textureName, pngData)` | 使用与替换索引相同的文件名规则写入原图 PNG，不覆盖已有文件；由纹理补丁在未命中时调用 |
| `DumpManager.Flush()` | 写入两个文本缓冲并返回是否全部成功 |

I2 查询 Hook 转交未翻译的文本词条，不修改游戏原结果。通用文本正常查询接口仅在加载完成后导出未命中的原文；`IsInTranslationDictionary` 仍只探测词库，不产生导出副作用。首次加载期间不会把尚未就绪的整个词库误当作缺失翻译导出。通用文本显示 Hook 覆盖系统消息队列与 TMP / uGUI 文本。TMP / uGUI 入口通过 `TryGetDisplayTranslation` 查询，加载完成后未命中时调用 `DumpDisplayText` 导出；调用前先查 `IsTextDumped`，只为新原文构造场景名和路径。纹理补丁负责在未命中时编码原图并交给导出设施，其余显示入口仍需游戏接入。

文本写入失败会保留缓冲并尝试恢复原文件长度；PNG 通过临时文件和不覆盖目标的移动操作发布。导出去重记录在资源重载时保留，与 XUAT 的已译文字登记集合彼此独立，不作为翻译查询缓存。开关、阈值与落盘触发条件见[资源指南](翻译指南.md)。

## 7. XUAT 互操作

采用 JAT 的判定拦截方式，反射查找已加载的 `XUnity.AutoTranslator.Plugin.Core`，不需要编译期引用或把 XUAT DLL 放入 `lib`。匹配下列类型中返回 `bool`、第一个参数为 `string` 的 `IsTranslatable` 方法：

- `Utilities.LanguageHelper`
- `TextTranslationCache`
- `CompositeTextTranslationCache`

判定顺序：

1. 输入已登记为 NET 的 UI 或通用文本译文时，返回 `false`，阻止 XUAT 再翻译。
2. 通用文本显示 Hook 已接管，且当前原文能通过精确或正则查询翻译时，也返回 `false`，交给 NET。
3. 其余情况保留 XUAT 原判定；NET 判定发生异常时同样放行，不把全部文本误封。

**第 2 项只在显示 Hook 确实安装后生效。** `TextTranslateManager.Init` 按 `TextTranslatePatch.Install()` 的结果调用 `SetDisplayHooksInstalled`，移除补丁或卸载模块时复位为 false；这不是供翻译包开启的设置。显示 Hook 通过一个补丁类覆盖多个入口：系统消息队列与 TMP / uGUI 文本。因此该拦截意味着词库内原文不再交给 XUAT，覆盖面仍限于已接入的入口。限制：显示 Hook 安装期间，第 2 项对所有词库内原文都拒绝 XUAT；这类原文若经由被排除的调用上下文或未接入的路径显示到屏幕上（见第 8 节），两个插件都不会翻译它。

译文登记与查询接口：

- 通用文本 `TryGetTranslation` 在互操作启用时跳过已登记的 NET 译文，并在成功返回后登记结果。
- `IsInTranslationDictionary` 只判断翻译能力，不登记候选结果，避免一次探测就被当作已经输出。
- UI 在参数、RTL 和 `AdvancedFormat` 全部成功后，才通过 `MarkTranslated` 登记最终结果，不登记未展开的模板。
- 两个管理器分别提供 `IsNetTranslatedText` 和 `MarkTranslated`。后续显示 Hook 若还会修改返回值，应登记实际提交的最终文本。
- UI 和通用文本使用独立、线程安全、Ordinal 匹配的译文集合；成功发布新资源或卸载模块时清空各自集合，加载失败仍保留旧状态。
- 集合只用于防重译，不用来返回缓存译文；不包含未命中记录或 LRU，也不做额外规范化、反转义或占位符推测。

除这些集合外，TMP / uGUI 入口还在 `DisplayTextRecords` 中按组件保存显示记录：组件、原文，以及 Hook 写入的译文。游戏再次向同一组件写入这段译文时，Hook 直接放行，不再查询。因此即使没有 XUAT，NET 也能按组件识别自己的输出，而且不依赖目标语言。记录从不回答查询，也不是缓存：每个新原文仍要经过词库查询。安装了 XUAT 时，`TryGetDisplayTranslation` 仍会通过 `MarkTranslated` 登记最终文本，让 XUAT 跳过它。

限制：游戏代码可能把 NET 的输出从一个组件复制到另一个组件，而目标组件没有这份副本的记录。未安装 XUAT 时，副本会再次进入查询，未命中时还会进入导出。第 8 节的回读上下文覆盖了已知的复制位置。

限制：安装 XUAT 时，XUAT 会通过相同的 TMP 与 uGUI setter 写入它自己的译文。Hook 把每次这样的写入都视为新的游戏文字，因此未命中时 XUAT 的译文会作为 `original` 进入导出。

插件 `Start` 尝试初始化；晚加载的程序集通过加载事件向 Unity 同步上下文投递回调，在主线程安装补丁，不依赖 `Update` 轮询。互操作卸载后，已排队的回调不再执行安装。未安装 XUAT 时保持普通 NET 行为；签名不兼容或安装失败会记录警告。卸载只移除 NET 自己的 Harmony 补丁，并取消程序集加载事件订阅。

默认启用 `2General` 下的 `EnableXUATInterop/启用 XUAT 互操作`。`XUATInterop.IsInstalled` 和 `PatchedMethodCount` 可用于接入诊断。反射兼容检查不等于真实 XUAT 版本或游戏运行验证。

实现见 [XUATInterop.cs](../../CRC3D3.NotEnoughTranslator.Plugin/Utils/XUATInterop.cs) 和 [TranslatedTextRegistry.cs](../../CRC3D3.NotEnoughTranslator.Plugin/Translation/TranslatedTextRegistry.cs)。

## 8. 后续接入要求

- 通用文本 Hook 只替换显示值，不修改兼作业务键的名称、CSV 数据或游戏状态。
- 通用文本新增显示入口统一加入 `Hooks/Text/TextTranslatePatch.cs`，复用同一个 Harmony ID 和 `Translate` 辅助方法：加一个带 `[HarmonyPatch]` 的方法即可被 `PatchAll` 装上，不按入口另建补丁类。
- 需要处理 I2 调用上下文隔离，避免二次翻译 I2 已处理的显示结果。
- 不能仅凭组件是否挂了 `Localize` 就永久跳过通用翻译；同一个组件仍可能被直接赋值。
- 纹理接入需在 Unity 主线程创建与管理 `Texture` / `Sprite`，明确原资源与替换资源的生命周期。
- 不将当前查询接口或加载计数视为实机覆盖率证明。

### TMP / uGUI 显示入口

`TMP_Text.text` setter、`TMP_Text.SetText(string, bool)` 和 `UnityEngine.UI.Text.text` setter 上的前置补丁翻译每次写入。预制体里序列化的文字不经过 setter 就会显示，因此 `TextMeshProUGUI.OnEnable` 和 `UnityEngine.UI.Text.OnEnable` 的前置补丁会读取当前文字；命中时先写入记录，再通过 setter 赋值译文。所有入口沿用系统消息入口的原文过滤：空白文字、数字和已登记的输出原样通过。写入命中时设置该组件的记录，未命中时删除记录。加载完成后的未命中还会连同场景名和路径导出原文。

排除的调用上下文：每个上下文用一个深度计数器标记，做法同 `UITextTranslatePatch` 的 `_explicitLanguageDepth`。前置方法加一，异常清理方法减一，抛出异常时也会减。深度大于 0 时，Hook 不查询也不导出这次写入，而是删除该组件的记录，并给它打上排除写入者标记。

| 上下文 | 目标 | 原因 |
| --- | --- | --- |
| 剧情窗口 | `AdvSystem.MessageDisplayClassicStyle.charaNameText` 与 `messageText` setter、`AdvSystem.NewStyleMessageBlock.SetText(TMP_Text, string)` | 剧情文本和说话人名属于剧本显示入口。打字机效果的写入和其他消息调用方也都经过这些写入方法。 |
| 对话记录 | `AdvSystem.BackLogMessageUnit.SetMessage(MessageData)` | 对话记录也是剧情文本。没有这个上下文时，对话记录会显示译文，而剧情窗口仍显示原文。 |
| 剧情选项 | `AdvSystem.ChoicesButton.SetData(ADVKagManager.ChoiceData)` | 选项按钮显示的选项文字属于剧本显示入口。没有这个上下文时，界面 Hook 会把每个选项当作界面标签查询和导出。 |
| 输入框 | `TMPro.TMP_InputField.UpdateLabel` | 它写入玩家输入的文字，输入的文字不能进入查询或导出。占位提示是普通 TMP 文字，照常翻译。 |
| NET 输出 | `CRC.UI.SystemMessage.ShowSystemMessage(string)` | 该标签显示系统消息入口的输出。未安装 XUAT 时 `MarkTranslated` 不登记任何内容，只有这个上下文能避免该输出被再次查询。 |
| I2 输出 | `I2.Loc.LocalizeTarget_TextMeshPro_UGUI.DoLocalize`、`LocalizeTarget_TextMeshPro_Label.DoLocalize`、`LocalizeTarget_UnityUI_Text.DoLocalize`、`I2.Loc.LocalizeDropdown.OnLocalize` | 这些方法把 I2 结果写入 TMP 和 uGUI 标签，即上文要求的 I2 调用上下文隔离。 |

`OnEnable` 前置补丁和刷新都在所有调用上下文之外运行，会跳过带排除写入者标记的组件。之后只要有一次在所有上下文之外的写入，标记就会清除。因此标记跟随最近一次观察到的写入者，从不永久生效。游戏直接给挂了 `Localize` 的组件赋值时，这次写入仍会经过通用翻译，符合上文关于 `Localize` 的要求。

回读上下文：部分游戏代码会读回标签文字，再保存、比较或复制。在回读上下文中，`TMP_Text.text` getter 的后置补丁会检查组件：若它仍显示记录中的译文，getter 返回记录中的原文。回读上下文中的写入照常翻译。不在任何回读上下文中时，后置补丁只读取一个计数器。

| 目标 | 读取的值 | 原因 |
| --- | --- | --- |
| `CRCRomanceSystem.RomanceMenuControl.Start`、`PlayFlowONOFF`、`RomanceMessageONOFF` | ON / OFF 开关标签 | 游戏把标签文字存入 `romanceMenuPlayFlow` / `romanceMenuMessage`，保存配置时写入文件。 |
| `RomanceMenuControl.OnEnable` | 按钮标签中的 `[SF]` 与 `[HF]` | 游戏把标签文字中的这些标记替换为已保存的名字。 |
| `CRC.UI.TopicListManager.Open`、`NameFilter`、`ExpirationTypeFilter` | 筛选标签 | 游戏用标签文字与原文分类名比较，并复制到新标签。点击监听器在任何上下文之外传入标签文字，因此 `NameFilter` 和 `ExpirationTypeFilter` 的前置方法还会在上下文内读取条目的 `FilterName`，替换参数 `name`。 |
| `CRC.UI.SNS.SNSExpandWindow.OpenWindow` | 六个帖子标签 | 窗口把这些标签复制到自己的标签。在上下文中复制的是原文，再由写入入口翻译。尚未经过游戏内验证。 |
| `CRCRomanceSystem.StatusPanelControl.RefreshFromSession` | 状态文字、玩法名、玩法性格 | 面板每帧把标签文字与新的日文值比较，只在变化时写入。在上下文中比较看到的是原文，因此已译标签不会每帧重写并再次查询。 |

已知限制：

- `SNSTrendTabManager` 只显示译文的前 30 个字符。
- `ShowCookingRecipeItemChain.ChangeData` 和 `ScoreFalse.Move` 用 `text += line` 拼接标签，这些标签会显示混合文字，每一步都可能新增一条导出记录。
- `FishingGameManager.Cast_FollowCastFishName` 在玩家瞄准期间每帧把鱼名标签与日文鱼名比较。已译鱼名使比较失败，因此该标签每帧重写并再次查询。若在此加读取上下文，名牌宽度会按日文长度计算，所以这里不加上下文。

## 9. 构建

目标环境：.NET Framework 4.8 / Unity 2022.3 / BepInEx 5。

将 CRC 对应版本的下列程序集放入仓库根目录 `lib`：

- `I2.Localization.dll`
- `WfSystem.FileSystem.dll`
- `UnityEngine.UI.dll`
- `Unity.TextMeshPro.dll`
- `Assembly-CSharp.dll`
- `Assembly-CSharp-firstpass.dll`

在仓库根目录执行：

```powershell
dotnet build CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin.csproj -c Release
```

异步使用 `Task`，不引入 `System.Threading.Tasks.Extensions` / `ValueTask` 的额外运行时依赖。编译成功不等于完成实机验证。

CI 编译同一个工程：`.github/workflows/build.yml` 会先把这六个程序集从私有仓库 `MeidoPromotionAssociation/CRC3D3.GameLibs` 拉到 `lib`，所以它们不会被提交进这个公开仓库。该仓库按游戏版本分目录（如 `2.49.2/`、`demo2/`），要编哪个版本由 `.github/scripts/fetch_game_libs.sh` 顶部的 `DEFAULT_VERSION` 决定，也可用仓库变量 `GAME_LIBS_VERSION` 覆盖。推送与 `PluginVersion` 一致的 tag 时还会跑 `.github/workflows/release.yml`，完成打包与发布。
